# Plan

Предлагаю следующий рефакторинг посвятить каталогу Cloudinary и webhook. Объём ограничим этими двумя связанными частями.

1. Разобрать текущие сценарии каталога. Зафиксировать поведение при пустой папке, ошибке Cloudinary, отсутствии настроек и неподдерживаемом способе поиска папки. Это даст ясные условия для исправления.
2. Сделать единый источник настройки папки. Каталог и webhook будут выбирать папку по одному правилу. Сохраним совместимость с текущими переменными окружения.
3. Исправить обработку ошибок каталога. Отделить успешный пустой ответ от сбоя запроса. Сбой не должен превращаться в пустой результат, который затем попадёт в кэш. Галерея при этом должна продолжать показывать базовый каталог.
4. Укрепить webhook. Проверять обязательные заголовки и размер запроса до разбора тела, безопасно обрабатывать ошибочный JSON, принимать события только для нужной папки и возвращать правдивое значение revalidated.
5. Добавить проверки этих сценариев. Проверить пустую папку, отказ Cloudinary, оба способа поиска папки, неверную подпись, некорректный JSON и событие из другой папки. Затем запустить lint, тесты и сборку.

Готовый результат: сбой Cloudinary не выглядит как пустая галерея, webhook обновляет нужный каталог, а поведение закреплено проверками. Ротацию, дизайн и параметры доставки изображений в этот рефакторинг не включаю.

## Результаты

### Пункт 1. Исходное поведение каталога Cloudinary

Локальная проверка завершена. Ожидается ручная проверка перед пунктом 2.

Временный скрипт запускал текущие функции каталога с `unstable_cache` из Next.js 16.4.6. Методы SDK Cloudinary возвращали заданные ответы, а хранилище кэша работало в памяти. Для проверки отображения скрипт рендерил компоненты `/gallery` и `/list` и сверял HTML. Запросов к Cloudinary или Vercel не было. Изменения кода приложения и постоянные тесты в этот пункт не входили.

Отдельно воспроизвели ошибку при обновлении заполненного кэша. Первая загрузка записала одну фотографию. После отметки записи как устаревшей запрос ещё получил эту фотографию. Фоновый поиск завершился ошибкой, приложение вернуло `[]`, и кэш записал это значение. Следующий рендер показал `Gallery: 0`, а `/list` показал 972 фотографии из встроенного каталога. Главная, Cloud Grid и Time Grid используют тот же объединённый каталог.

При чтении кода также выявилось различие в настройке папки. Каталог выбирает её в порядке `CLOUDINARY_GALLERY_FOLDER` → `CLOUDINARY_FOLDER` → `gallery`, а webhook пропускает `CLOUDINARY_FOLDER`. Централизация этой настройки относится к пункту 2. Различие между пустой папкой и ошибкой, сохранение успешного кэша и исключение смешивания двух результатов относятся к пункту 3.
